How to use

Hi! This niche site is made for using exact find replace coding blocks from LLMs (fuzzy matching not yet supported sorry 💔)

Suggested use for Patcher when vibe coding.

1) I suggest using the provided PDF when working with an LLM to ensure markdown format acceptable to Patcher. You can alternatively make sure the AIA you are using provides exact find and replace code blocks using this example markdown format. Please keep in mind fuzzy matching isn't supported here yet, so the code blocks it provides must be entirely unabbreviated:

Patch 1/2
Find
```html
Old code here
</div>
```
Replace with 
```html
New code here 
```

Patch 2/2
Find
```html
<p> hello world</p>
</div>
```
Replace with 
```html
<p> hello again world</p> 
```

2) When ready, upload your current file that needs the patches applied (index.html, etc)

3) Use the button or manual textbox to paste your LLM's entire response that includes the markdown find and replace blocks. You don't need to erase the intro, outro, or other filler texts since Patcher uses regex to look just at the targeted markdown code blocks.

4) Patcher will immediately tell you which patches went through right, and let you download the new file with all successful patches.

5) Unsuccessful patches are individually skipped; tapping or clicking on them should highlight where the markdown code struggled to find a find block etc.

6) Feel free to view this website's code directly on GitHub.com/spamfan/patcher to modify to your own uses!! :) If you're new to vibe coding or don't feel like you have a comfortable vibe coding LLM setup, I recommend also seeing my AI Studio vibe coding recommendations.

Suggested LLM workflow and resources

NOTE: I don't really know much of vibe coding but this is a flow that has worked well for me. While you could probably utilize this for other LLMs, this guide is especially tailored for using Gemini pro via AI studio.

Why is low token count important?

Keeping the context tokens in a chat as low as possible gives LLMs more clarity, speed, and less hallucinations.

Example: user makes an app, has an entire 8 messages between themselves and the AIA on modifying the app to support dark mode. The user follows through then realizes they don't want dark mode. It is incredibly more efficient for the user and LLM to delete these 8 messages rather than "modifying" the file again to get back to its starting point. Anytime the LLM is talked to, it has to re-read the entire conversation and restructure the initial html with all patches. This is why rebranching and deleting irrelevant pieces is highly important. I find the most efficiency as only using one AI agent for one version change most the time, then rebranching when working on more features.

  1. I recommend starting a new AI studio conversation with the latest available free (DO NOT ATTACH CARD) pro model such as Gemini 3.1 pro etc. I recommend using these settings:
    • Temperature: 0.8
    • URL context; on
    • Grounding with Google search: on
    • Grounding with Google maps: only turn this on if the project you're working on uses realtime map information (rare)
    • Code execution: on (turn this on as a last priority if it lets you, if it doesn't I won't worry about it, the others are more important imo.)
    • Top p limit, output length, etc: these and any other settings are usually fine to leave on default.
  2. In the new prompt, I recommend uploading the attached LDD.pdf or your own version. (Once a project becomes large enough I add more sections to the LDD for my specific project/ecosystem)
  3. If you have important project files the AIA should know, such as an HTML codebase etc I recommend uploading that now with the LDD.
  4. You can usually leave your introduction blank and just let it read the attachments and run.
  5. If you're making a new application, I suggest letting it eventually create the codebase for you. I suggest all subsequent changes use find and replace blocks.
  6. Once enough changes have been made, anywhere between 1-10 individual sets of patches, and/or when context tokens = 100-150k, I highly recommend "rebranching" the chat.
  7. To rebranch, simply scroll to the top of the chat where the LDD and index were uploaded (incl your intro if wanted.). Click more options>branch from here.
  8. In the branched off chat, double check the settings are how you wanted them. Delete and reupload any updated media, such as your LDD if you have a newer one, or (more likely) your newest codebase versions (most current index.html etc etc)
  9. If a conversation with AI Studio takes a detour, or any other chunk of conversation ends up becoming irrelevant (example: your discussion with an AI regarding potential code solutions you chose not to pursue, conversational errors on either individual parts etc etc), it's highly recommended to delete that part of the conversation and correct it if applicable. This keeps context limits down.
  10. When the AI is onto the patches phase, simply click its entire response > more options > Copy as markdown, and paste its whole response into Patcher. Upload your codebase needing patches to Patcher and download the output if successful.
